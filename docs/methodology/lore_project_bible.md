# ФинПульс: Gate 3 / Project Bible для production lore pipeline

**Статус:** Gate 3 approved for Gate 4 / Macro Arc.

**Дата подготовки:** 2026-07-05.

**Граница approval:** документ прошёл human approval Gate 3. Следующий
разрешённый gate - Gate 4 / Macro Arc.

**Human decision 2026-07-07:** финальный список объектов уровней закреплён в
разделе 10.4. Остальная граница Gate 3 и approval перед Gate 4 сохраняются.

**Human decision 2026-07-08:** Project Bible утверждён как Gate 3 source of
truth для Gate 4 / Macro Arc. Новая работа остаётся универсальной рамкой без
настраиваемой отраслевой оболочки. На каждом уровне пользователь выбирает один
из двух закреплённых объектов текущего уровня и собирает выбранный объект по
мере прохождения уровня.

## 1. Назначение документа

Project Bible фиксирует устойчивый центр будущей финансово-эмоциональной
истории ФинПульс: героя, мир, новую работу, роль «Доски», правила эмоций,
границы NPC, правила тона, финансовую безопасность и связь с компетенциями.

Документ нужен, чтобы следующие gate-артефакты не достраивали базовые решения
случайно и не перепрыгивали сразу к структуре уровней, разделов, эмоций,
уроков или экранов.

Project Bible отвечает на вопросы:

1. Какой мир уже считается каноном после Gate 1-2.
2. Каким человеком герой является в начале истории.
3. Как город, работа, NPC, эмоции и «Доска» должны служить финансовым
   компетенциям.
4. Какие safety, privacy и education-vs-advice правила обязательны для всех
   следующих gates.
5. Какие решения человек должен принять перед Gate 4 / Macro Arc.

## 3. Что Gate 3 делает и чего не делает

Gate 3 делает:

- фиксирует правила мира, героя, города, работы, NPC, «Доски», эмоций и тона;
- закрепляет финальный список объектов уровней по human decision от
  2026-07-07;
- описывает начальное состояние героя без полного сюжета;
- формулирует главную трансформацию героя на 5 уровней как направление роста,
  а не как Macro Arc;
- задаёт privacy/B2B boundary для текущего MVP и будущих гипотез;
- задаёт financial safety и fact-check правила для следующих gates;
- фиксирует, как использовать Gate 2 competency IDs при будущих действиях
  пользователя;
- формулирует решения человека перед Gate 4 / Macro Arc.

Gate 3 не делает:

- не создаёт Macro Arc на 5 уровней;
- не создаёт Section Grid из 20 разделов;
- не создаёт Emotional Model или список 20 эмоций;
- не создаёт Traceability Matrix;
- не создаёт Lesson Cards, Screen Scripts или 80 уроков;
- не утверждает финальный список NPC, но задаёт рабочий набор NPC-функций для
  human review;
- не создаёт детали объектов на 16 уроков и не привязывает объекты к событиям
  Macro Arc;
- не меняет runtime JSON, schemas, frontend/backend code, API или persistence;
- не добавляет диагностики, HR-аналитику, B2B-дашборды, rewards, streak,
  challenges или новые product mechanics;
- не превращает образовательные объяснения в персональные финансовые,
  инвестиционные, налоговые или юридические рекомендации.

## 4. Канон после Gate 1-2

Основание для входа в Gate 3: направление Gate 2 было одобрено человеком в
чате словами «Мне всё нравится». Это разрешает перейти к Project Bible, но не
разрешает перепрыгивать к Macro Arc, Section Grid, Emotional Model,
Traceability Matrix, Lesson Cards, Screen Scripts или генерации 80 уроков.

После Gate 1 / Source Pack и Gate 2 / Competency Table каноном считается:

- production lore pipeline работает gated-порядком:
  Source Pack -> Competency Table -> Project Bible -> Macro Arc -> Section Grid
  -> Emotional Model -> Traceability Matrix -> Lesson Cards -> Screen Scripts
  -> Vertical Slice -> audits -> handoff;
- будущая production-геометрия лора остаётся целевой рамкой `5 уровней x 4
  раздела x 4 урока = 80 уроков`, но текущий MVP остаётся на 16 опубликованных
  уроках Уровня 1;
- текущая runtime-иерархия проекта остаётся только
  `Program -> Level -> Section -> Lesson -> Card`;
- adult competency catalog является source of truth для покрытия тем, но не для
  текущих ставок, лимитов, тарифов, вычетов или правовых значений;
- Gate 2 competency IDs `MNY-*`, `PLN-*`, `RSK-*`, `ENV-*` являются рабочей
  production-схемой для Gate 3; перед Traceability Matrix человек может
  подтвердить, расширить или заменить эту схему;
- каждый будущий урок должен иметь четыре якоря: сюжет, эмоция, финансовая
  компетенция и игровое действие пользователя;
- игровое действие должно проверять компетенцию, а не быть декоративным;
- «Доска» является центральной визуально-сюжетной метафорой будущего лора, но
  не является текущей runtime-механикой MVP;
- объекты уровней закреплены в этом Project Bible; эмоция раздела и деталь
  урока остаются принципами будущей production-рамки, а не утверждёнными
  финальными списками;
- личные ответы пользователя о деньгах не оцениваются как хорошие, плохие,
  правильные или неправильные;
- продукт не обещает доход, богатство, успех, материальный результат или
  улучшение финансового положения как следствие прохождения курса.

## 5. Foundation мира

Мир ФинПульс - это современная взрослая финансовая среда, показанная через
переезд героя в новый город и выход на новую работу.

Стабильная рамка мира:

- **герой:** взрослый человек в моменте новой самостоятельности, который уже
  живёт в ритме доходов, расходов, решений, ошибок и
  обязательств;
- **город:** собирательный современный российский город без жёсткой региональной
  привязки, где финансовые ситуации возникают в быту, транспорте, аренде,
  сервисах, договорах, маркетплейсах, банках, госканалах и цифровых сообщениях;
- **новая работа:** источник регулярного дохода, нового статуса, давления,
  отношений, ожиданий и возможностей роста;
- **тон:** взрослый, спокойный, уважительный, без стыда, без детской внешней
  наградности и без драматизации бедности или успеха;
- **реализм:** ситуации должны быть узнаваемыми, но не документальными кейсами
  про конкретных людей, компании, банки, брокеров или госорганы;
- **финансовые компетенции:** каждая будущая ситуация существует потому, что
  помогает проверить действие из competency table;
- **связь с «Доской»:** «Доска» делает путь видимым как символ ясности и
  собранности, но не заменяет личный Навигатор и не обещает материального
  результата.

Мир не должен быть:

- корпоративным HR-симулятором;
- городостроительной картой уровней;
- набором лекционных тем с декоративным сюжетом;
- медицинской или психологической моделью диагностики;
- витриной финансовых продуктов.

## 6. Герой

Герой - не идеальный ученик и не карикатурный «финансово неграмотный» персонаж.
Он достаточно взрослый, чтобы нести ответственность за решения, и достаточно
перегруженный новым этапом, чтобы ошибаться, откладывать, торопиться,
избегать сложных тем и путать эмоциональный импульс с финансовым решением.

### 6.1. Стартовое состояние

| Параметр | Project Bible boundary |
|---|---|
| Жизненный этап | Начало нового самостоятельного этапа: переезд, аренда или обустройство жилья, новый рабочий ритм, личный денежный поток. |
| Причина переезда | Возможность работы, смены карьерного трека. |
| Причина выхода на новую работу | Герой получает регулярный доход и новые обязательства; работа становится точкой входа в финансовые ситуации, а не HR-продуктом. |
| Финансовая незрелость | Не видит полной картины денег, смешивает обязательное и желаемое, реагирует на давление, откладывает проверки, верит в простые ответы. |
| Эмоциональный паттерн | В состоянии неопределённости ищет быстрый способ снять напряжение: купить, согласиться, отложить, избежать разговора, поверить уверенной фразе. |
| Внешний запрос | «Мне нужно устроиться, не потеряться в городе и на работе, справиться с деньгами в новом ритме». |
| Внутренняя проблема | «Я хочу чувствовать контроль, но пока не отличаю сигнал эмоции от импульса решения». |

### 6.2. Допустимый диапазон героя

- Герой молодой специалист.
- Герой имеет имя и пол, а так же визуальную кастоимизацию (в будущей версии), но это не
  должно менять competency structure, Macro Arc или safety boundaries.
- Герой может ошибаться, но ошибки должны быть обучающими и уважительными:
  «ошибка показывает риск», а не «герой плохой с деньгами».
- Герой не должен становиться финансовым экспертом сразу после одного урока.
  Рост постепенный: он учится замечать, проверять, сравнивать, задавать вопросы
  и выбирать осознаннее.

### 6.3. Запреты для героя

- Не делать героя инфантильным, беспомощным или комически неразумным.
- Не делать героя универсальным носителем всех ошибок одновременно.
- Не делать героя «успешным победителем денег».
- Не использовать диагнозы, психотипы или эмоции как ярлыки героя.
- Не связывать ценность героя с доходом, должностью, покупками или имуществом.

## 7. Новый город

Город - это не карта уровней и не набор районов для Section Grid. На Gate 3 он
фиксируется как система финансовых ситуаций, в которой герой сталкивается с
новыми расходами, сервисами, правилами, предложениями, рисками и социальным
давлением.

Город должен создавать:

- бытовые решения: аренда, транспорт, покупки, подписки, ремонт, еда,
  маркетплейсы;
- финансовые интерфейсы: платежи, QR, переводы, автосписания, кредиты,
  договоры, страховые предложения, банковские приложения;
- источники информации: реклама, отзывы, блогеры, консультанты, официальные
  сайты, госканалы;
- социальные контексты: новые коллеги, соседи, друзья, семья на расстоянии,
  сервисные специалисты;
- риски неопределённости: незнакомые правила, срочные предложения, скрытые
  условия, манипулятивные сообщения, time-sensitive данные;
- возможности роста: найти источник, сравнить, спросить, зафиксировать правило,
  собрать личный ориентир.

Город не должен:

- иметь финальную карту уровней или разделов на Gate 3;
- быть привязанным к одному региону, доходу или социальному классу;
- требовать от пользователя раскрывать реальные адреса, счета, долги, зарплату
  или финансовые привычки;
- становиться декорацией без связи с competency IDs.

## 8. Новая работа

Новая работа - это источник дохода, ритма, отношений, давления и роста. Она
помогает показать взрослые финансовые ситуации через регулярную зарплату,
испытательный срок, рабочие ожидания, соцпакет, командировки, бытовые расходы,
неформальные просьбы, льготы и коммуникацию.

Базовая рамка новой работы - универсальное новое рабочее место / компания без
настраиваемой отраслевой оболочки. Gate 4 может использовать узнаваемые рабочие
ситуации, но не должен ветвить курс, компетенции, сюжет или примеры по отраслям.

Работа должна использоваться как:

- причина регулярного дохода и планирования месяца;
- источник новых обязательств и неопределённости;
- место социальных сравнений и давления, но без стыда;
- источник ситуаций про договоры, условия, льготы, страховки, налоги и права;
- площадка для разговоров с NPC, которые дают разные взгляды, но не решают за
  героя;
- контекст для тренировки soft skills: задать вопрос, проверить источник,
  отказаться от давления, сравнить условия, уточнить непонятное.

Работа не должна становиться:

- HR-аналитикой;
- B2B-дашбордом;
- продуктом для работодателя;
- сценарием оценки сотрудника;
- источником доступа работодателя к личным ответам, ошибкам, привычкам или
  финансовым данным героя/пользователя;
- настраиваемой отраслевой оболочкой курса.

## 9. Главная трансформация героя

Это направление внутреннего роста, а не Macro Arc. Здесь не задаются события,
кульминации, разделы, эмоции или уроки. Gate 4 должен превратить это
направление в варианты макроарки после human approval Gate 3.

| Уровень | Внутренний шаг роста | Финансовая зрелость как направление |
|---|---|---|
| 1. Старт | От хаоса к видимости. | Герой начинает видеть, куда уходят деньги, где есть риски платежей и какие решения требуют паузы. |
| 2. Опора | От реакции к плану. | Герой учится распределять месяц, отличать обязательства от желаний, держать место для резерва и проверять условия. |
| 3. Уверенный | От простых ответов к сравнению. | Герой связывает срок, риск, ликвидность, стоимость решения и источник информации. |
| 4. Стратег | От локальных решений к системе. | Герой осторожно работает с более сложными темами: кредиты, страхование, инвестиционные предложения, налоги, права и долгий горизонт. |
| 5. Наставник | От личного контроля к спокойной самостоятельности. | Герой умеет задавать вопросы, признавать неопределённость, искать официальные источники, не давать себе и другим универсальных советов. |

Запрет: эта таблица не является планом уровней, списком разделов или
утверждением, какие компетенции попадают в какой уровень. Она только задаёт
стабильный вектор роста для Gate 4.

## 10. «Доска» и символический прогресс

«Доска» - центральный визуально-сюжетный носитель будущего прогресса. В начале
истории она почти пустая. По мере обучения на ней появляются следы ясности:
собранные части, закреплённые ориентиры, визуальные признаки пройденных решений
и эмоции, которые нашли более зрелую роль.

### 10.1. Принципы объекта уровня

- Каждый целевой уровень имеет закреплённый объектный смысл и два допустимых
  объектных варианта: `Проект 1` и `Проект 2`.
- На каждом уровне пользователь в будущей production-версии выбирает один из
  двух объектов текущего уровня; детали этого уровня собирают выбранный объект.
- Выбор объекта является визуально-сюжетным выбором и не меняет competency
  structure, финансовую безопасность, последовательность gate-артефактов или
  privacy rules.
- Список объектов уровней закреплён в Gate 3 и используется как вход для Gate 4
  / Macro Arc.
- Объект уровня символизирует этап взросления героя, а не финансовую покупку.
- Объект не должен обещать, что пользователь получит комнату, машину, квартиру,
  дом, доход или другой материальный результат.
- Объект должен быть достаточно взрослым, нейтральным и визуально понятным.
- Объект должен быть связан с трансформацией героя, а не с внешней наградой.

### 10.2. Принципы детали урока

- Деталь - след выполненного действия и понимания, а не монета, балл или
  случайная награда.
- Деталь должна быть связана с будущей компетенцией или решением героя.
- Деталь не утверждается на Gate 3 для каждого урока.
- Деталь не должна подменять проверяемое финансовое действие.

### 10.3. Связь с Навигатором

Персональный финансовый навигатор остаётся личным образовательным артефактом
пользователя. «Доска» остаётся символическим лор-прогрессом героя. Если обе
модели будут использоваться в будущем, их нельзя смешивать так, чтобы личные
ответы пользователя становились видимыми работодателю или превращались в
скоринг.

### 10.4. Канон объектов уровней

Это финальный список объектов уровней для будущего production-лора. Он
закрепляет смысл уровня и два допустимых объектных варианта. Gate 4 должен
проектировать эти пары как выбор пользователя на каждом уровне: пользователь
выбирает один объект текущего уровня и затем собирает выбранный объект по мере
прохождения уровня. Gate 4 не должен заменять сами объекты без нового human
decision.

| Уровень | Смысл уровня | Проект 1 | Проект 2 |
|---|---|---|---|
| **1. Старт** | Личная база | **Комната** | **Личная мастерская** |
| **2. Опора** | Движение и самостоятельность | **Машина** | **Дом на колёсах** |
| **3. Уверенный** | Большое своё пространство | **Квартира** | **Студия-лофт** |
| **4. Стратег** | Большой личный проект | **Дом** | **Оранжерея** |
| **5. Наставник** | Пространство для других | **Гостевой двор** | **Открытая мастерская** |

Граница использования:

- объекты являются символами прогресса героя, а не финансовыми целями
  пользователя;
- выбор объекта не является диагностикой, скорингом, персонализацией финансового
  содержания или обещанием результата;
- объект не обещает реальную покупку, доход, статус, жильё, транспорт или
  улучшение финансового положения;
- детали объекта по 16 урокам каждого уровня проектируются позже и должны быть
  связаны с компетенциями, а не с внешней наградой;
- визуальный стиль, степень реализма и конкретные детали сборки остаются
  задачей Macro Arc, Section Grid и дальнейшего continuity design.

### 10.5. Рабочая лексика сквозных предметов

Это не список объектов уровней и не альтернатива канону из 10.4. Это рабочий
набор сквозных предметов мира для human review, чтобы будущая история имела
общую визуальную лексику до проектирования уровней, разделов и уроков.

| Объект | Функция | Граница использования |
|---|---|---|
| Пустая «Доска» | Центральное место, где хаос постепенно становится картой решений. | Не является runtime-механикой MVP и не хранит личные ответы пользователя. |
| Карта города / маршрутная карточка | Символ поиска пути, официального источника, маршрута жалобы или проверки. | Не превращается в карту Section Grid или карту уровней. |
| Папка условий / рабочий файл | Символ договоров, правил, документов, сроков и вопросов перед согласием. | Не даёт юридического заключения и не заменяет консультацию. |
| Конверт ориентиров | Символ бюджета, резерва, цели, границы и личного правила. | Не обещает накопление конкретной суммы или финансовый результат. |
| Лампа / отметка ясности | Символ момента, когда герой понял риск, источник или критерий выбора. | Не является наградой, score, streak или диагностическим индикатором. |

Перед Gate 4 человек может утвердить, заменить или сузить этот набор
предметов. Gate 4 может использовать его только как лексику мира, а не как
замену объектам уровней, разделам или урокам.

## 11. NPC principles

NPC нужны не как финальный список персонажей, а как функции взрослой финансовой
среды. Gate 3 фиксирует допустимые роли и запреты. Финальный набор персонажей
может появиться только после Macro Arc и связанных решений человека.

### 11.1. Функции NPC

NPC могут:

- создавать жизненную ситуацию, в которой герой должен проверить, сравнить,
  уточнить или отказаться;
- показывать разные человеческие отношения к деньгам без ярлыков;
- задавать давление, сомнение, социальное сравнение или поддержку;
- приносить внешний контекст: договор, сообщение, предложение, ошибку,
  официальный источник, спорную рекламу;
- помогать увидеть эмоциональный импульс и отделить его от действия;
- возвращаться как continuity-опора, если это будет утверждено в Macro Arc.

### 11.2. Допустимые роли

Допустимые типы ролей без утверждения финального списка:

- коллега или наставник на работе;
- сосед, арендодатель или человек из бытового сервиса;
- друг или знакомый в новом городе;
- член семьи или близкий человек на расстоянии;
- представитель сервиса, банка, страховой, маркетплейса или госканала как
  ситуационная роль;
- человек, который создаёт давление или демонстрирует типичную ошибку, но не
  становится злодеем.

### 11.3. Запреты для NPC

- NPC не должны давать персональные финансовые, инвестиционные, налоговые или
  юридические советы.
- NPC не должны быть скрытой рекламой банка, брокера, страховой, продукта,
  работодателя или платформы.
- NPC не должны стыдить героя или пользователя за прошлые решения.
- NPC не должны подтверждать диагноз, психотип, «финансовую зрелость» или
  качество личных ответов пользователя.
- NPC не должны решать финансовую задачу вместо пользователя.

### 11.4. Риск скрытых рекомендаций

Если NPC произносит уверенную фразу о кредите, инвестиции, страховке, налоге,
пенсии, крипто/FOREX или недвижимости, текст должен явно оставаться на уровне
образовательного объяснения: риски, альтернативы, источник, дата актуальности,
границы примера. Решение за героя или пользователя недопустимо.

### 11.5. Рабочий набор сквозных NPC-функций

Это не финальный список персонажей и не список 20 NPC. Это 5 рабочих
функциональных архетипов для human review, чтобы Gate 4 мог проектировать Macro
Arc без случайных ролей.

| NPC-функция | Что приносит в историю | Запрет |
|---|---|---|
| Наставник-практик | Помогает герою сформулировать вопрос, найти источник, не торопиться с выводом. | Не выбирает продукт и не говорит, что герою «надо» делать. |
| Коллега-зеркало | Нормализует неопределённость нового места, показывает похожие сомнения без стыда. | Не превращается в HR-оценщика или канал работодателя. |
| Носитель давления | Создаёт социальное, потребительское или статусное давление, которое герой учится замечать. | Не высмеивается и не становится злодеем. |
| Институциональная роль | Представляет договор, сервис, банк, страховую, госканал, маркетплейс или официальную процедуру. | Не рекламирует организацию и не выступает персональным консультантом. |
| Бытовой якорь | Возвращает героя к жизни вне работы: жильё, семья, соседство, повседневные платежи. | Не требует раскрытия чувствительных личных данных пользователя. |

Перед Gate 4 человек может утвердить, заменить или сократить эти функции. Имена,
биографии, отношения и частота появления остаются задачей Macro Arc и
continuity design после human approval.

## 12. Emotion principles

Эмоции в будущем лоре - не враги героя и не диагноз. Они являются сигналами,
которые могут запускать импульс, риск и более зрелое действие.

Базовая формула:

```text
эмоция -> импульс -> риск -> осознание -> инструмент -> зрелое действие
```

Правила:

- одна будущая эмоция раздела должна быть связана с финансовым риском и
  проверяемой компетенцией;
- эмоция должна иметь полезный сигнал, а не только «негатив»;
- герой не «побеждает» и не «исправляет» эмоцию;
- пользователь не получает психологический диагноз, ярлык или оценку;
- личные ответы о чувствах принимаются как субъективные артефакты, а не
  проверяются как правильные;
- список 20 эмоций не утверждается в Gate 3;
- эмоциональная модель 20 разделов не создаётся в Gate 3.

Запрещённые фреймы:

- «победить тревогу»;
- «избавиться от стыда»;
- «исправить неправильную эмоцию»;
- «вы тревожный/транжира/избегающий» как ярлык пользователя;
- «после урока эмоция больше не мешает»;
- «спокойствие» как медицинский или психологический показатель.

Безопасный фокус:

- «заметить сигнал»;
- «сделать паузу»;
- «проверить источник»;
- «разобрать условия»;
- «выбрать следующий учебный шаг»;
- «сформулировать вопрос или правило».

## 13. Financial safety and fact-check rules

Все следующие gate-артефакты должны удерживать финансовое содержание в границах
образования.

### 13.1. Education-vs-advice boundary

Разрешено:

- объяснять финансовую механику, понятия, риски и ограничения;
- показывать учебные примеры с условными данными;
- сравнивать критерии выбора без выбора продукта за пользователя;
- учить находить официальный источник и задавать вопросы;
- отделять durable-принцип от jurisdiction-specific и time-sensitive данных.

Запрещено:

- говорить «вам следует купить / вложить / оформить / продать / открыть»;
- выбирать банк, брокера, актив, страховой полис, налоговый режим, НПФ или
  программу за пользователя;
- обещать доходность, экономию, отсутствие риска, богатство, успех или
  материальный результат;
- делать персональные расчёты и выводы там, где нужна личная оценка ситуации;
- использовать срочность, дефицит, страх или стыд как мотивацию.

### 13.2. Factual stability

| Тип утверждения | Правило |
|---|---|
| Durable-принцип | Можно объяснять как устойчивую механику без свежего числа: риск-доходность, инфляция как снижение покупательной способности, сложный процент, ликвидность. |
| Jurisdiction-specific | Указывать юрисдикцию и официальный источник. Не переносить правила РФ на другие страны. |
| Time-sensitive | Не зашивать как вечный факт. Если число нужно, указывать источник и дату актуальности. |
| Спорное / интерпретive | Помечать как ориентир, подход или гипотезу, а не норму или закон. |

### 13.3. High-risk topics

Темы повышенного риска должны помечаться и проверяться отдельно:

- инвестиции, доходность, портфель, ИИС, диверсификация;
- кредиты, ПСК, долговая нагрузка, просрочка, реструктуризация, банкротство;
- налоги, вычеты, пособия, льготы, самозанятость, ИП;
- страхование, ОСАГО, период охлаждения, мисселинг, допуслуги;
- пенсии, НПФ, ПДС, долгосрочные программы;
- валютные операции, зарубежные покупки, валютный контроль и отчётность;
- криптоактивы, FOREX, high-risk digital offers;
- недвижимость, ипотека и крупные долгосрочные обязательства;
- предпринимательство, самозанятость, ИП, налоговые режимы, контрагенты;
- права потребителей финансовых услуг, жалобы, суды и официальные маршруты
  обращения;
- мошенничество, социальная инженерия, дипфейки, персональные данные.

### 13.4. Topic-specific safe handling

- **Инвестиции:** объяснять риск, срок, ликвидность, комиссии, диверсификацию и
  отсутствие гарантий; не давать buy/sell advice, прогнозы или названия
  «выгодных» активов.
- **Кредиты:** объяснять ПСК, переплату, срок, платёж, дополнительные услуги и
  долговую нагрузку; не говорить брать или не брать кредит.
- **Налоги:** объяснять общую механику и источник проверки; не давать
  индивидуальную налоговую оптимизацию.
- **Страхование:** объяснять риск, покрытие, исключения, вопросы к договору и
  мисселинг; не советовать конкретный полис.
- **Пенсии:** объяснять долгий горизонт, типы источников и необходимость
  проверки официальных условий; не выбирать программу за человека.
- **Крипто/FOREX:** фокусироваться на красных флагах, волатильности,
  юрисдикционных рисках и мошенничестве; не описывать как способ заработать.

### 13.5. Safe phrase library

Безопасные формулировки для следующих gates:

- «Это образовательное объяснение, а не индивидуальная финансовая
  рекомендация».
- «Один из подходов - смотреть на цель, срок, риск, ликвидность, комиссии и
  условия договора».
- «На учебных данных видно, как работает механизм; реальные условия проверяют
  в официальном источнике на дату обращения».
- «Высокая гарантированная доходность - красный флаг».
- «Личный ответ не оценивается как верный или неверный».
- «Если условия непонятны, безопасный учебный шаг - найти официальный источник
  или сформулировать вопрос специалисту».

## 14. Competency usage rules

Gate 2 competency IDs используются как рабочий язык всех будущих gates.

Правила:

1. Каждый будущий урок должен иметь одну главную competency ID.
2. Вторичные competency IDs допустимы только как фон или мостик.
3. Компетенция должна проявляться в действии пользователя: выбрать,
   классифицировать, сравнить, рассчитать на учебных данных, найти риск,
   проверить источник, упорядочить шаги, собрать черновик, сформулировать
   вопрос или micro-rule.
4. Если competency является установкой, будущая проверка должна быть помечена
   как `proxy-check`, а не как доказательство реального поведения.
5. Если competency high-risk или time-sensitive, будущий урок должен включать
   source/fact-check rule.
6. Competency table не является Traceability Matrix. Распределение
   компетенций по уровням, разделам и урокам происходит позже.
7. Competency ID не должна превращаться в лекционную тему без действия.

## 15. Game action rules

Игровое действие - это не декоративный клик и не награда. Оно должно проверять
образовательный результат.

Допустимые классы будущих действий:

- классифицировать операции, риски, источники, условия или цели;
- подсветить риск в договоре, рекламе, сообщении или предложении;
- упорядочить безопасные шаги;
- сравнить по заданным критериям;
- рассчитать на учебных данных;
- выбрать безопасный следующий шаг;
- собрать micro-rule или список вопросов;
- выбрать официальный источник;
- исправить ошибочную логику в учебном примере.

Правила:

- действие должно быть связано с competency ID;
- критерий успешности должен быть понятен;
- feedback должен объяснять финансовую логику, а не только «верно/неверно»;
- личные ответы не оцениваются как правильные или неправильные;
- действие не должно требовать раскрытия чувствительных личных финансовых
  данных;
- действие не должно создавать реальные reminders, streaks, rewards или
  diagnostics в текущем MVP.

## 16. Privacy and B2B boundary

Текущий MVP не добавляет B2B-контур, HR-аналитику, employer dashboards,
diagnostics или scoring.

Стабильные privacy rules:

- работодатель не видит личные ответы пользователя;
- работодатель не видит ошибки пользователя;
- работодатель не видит привычки, рефлексии, финансовые данные, доходы,
  расходы, долги, цели, ответы про эмоции или личные артефакты;
- будущие B2B-метрики возможны только после отдельного product/architecture
  decision;
- любые будущие B2B-метрики могут быть только агрегированными,
  обезличенными и защищёнными от деанонимизации;
- малые группы требуют порогов агрегации и отдельной privacy-проверки;
- корпоративная кастомизация города, компании или отрасли не должна менять
  competency structure, education-vs-advice boundary или приватность.

Формулировка, которую нужно сохранять для будущего B2B-контекста:

```text
Работодатель не видит ваши личные ответы и финансовые данные.
```

## 17. Tone guide

Тон Project Bible для будущих gates:

- взрослый, спокойный, точный;
- уважительный к ошибкам и неопределённости;
- без стыда, давления, морализаторства и сарказма;
- без обещаний «стать богатым», «добиться успеха», «разобраться навсегда»;
- без product placement и названий «лучших» финансовых организаций;
- без медицинских, психологических или юридических диагнозов;
- без детской внешней наградности;
- с опорой на действия: заметить, проверить, сравнить, задать вопрос,
  сформулировать правило, выбрать безопасный следующий шаг.

Юмор допустим только как лёгкое снижение напряжения в бытовой ситуации. Юмор не
должен быть направлен на бедность, долги, тревогу, ошибки, семью, профессию,
уровень дохода или личные ответы пользователя.

## 18. Anti-patterns

Запрещённые направления для следующих gates:

- писать Macro Arc до human approval Gate 3;
- строить 20 разделов или список 20 эмоций в Project Bible;
- генерировать 80 уроков или экранные сценарии;
- превращать героя в идеального ученика или комическую ошибку;
- делать город абстрактной доской уровней вместо источника финансовых ситуаций;
- делать работу HR-продуктом или каналом наблюдения работодателя;
- использовать NPC как рекламных консультантов;
- давать универсальные советы про кредиты, инвестиции, налоги, страхование,
  пенсии, крипто/FOREX или недвижимость;
- обещать материальный результат через объекты «Доски»;
- называть эмоции врагами;
- оценивать личные ответы пользователя;
- подменять competency action нажатием кнопки без проверки;
- зашивать time-sensitive числа без источника и даты;
- использовать старую карту 80 уроков, старые эмоции или старые разделы как
  production-канон без новой трассируемости.

## 20. Definition of Done для Gate 3

Gate 3 готов к Gate 4 / Macro Arc после human approval, если:

- документ находится в `docs/methodology/lore_project_bible.md`;
- назначение Project Bible зафиксировано;
- связанные источники перечислены явно;
- Gate 3 scope и non-goals описаны;
- канон после Gate 1-2 отделён от решений будущих gates;
- стабильная рамка мира описывает героя, город, работу, тон, реализм,
  компетенции и «Доску»;
- стартовое состояние героя описано без полного сюжета;
- главная трансформация героя на 5 уровней описана как направление, а не
  Macro Arc;
- город описан как система финансовых ситуаций без карты разделов;
- работа описана как источник дохода, давления, отношений и роста без
  HR-аналитики;
- NPC principles и рабочий набор 3-5 NPC-функций описаны без финального списка
  персонажей;
- принципы объектов «Доски», финальный список объектов уровней и рабочий набор
  3-5 сквозных предметов описаны без деталей объектов по урокам;
- emotion principles описаны без списка 20 эмоций и без диагностики;
- financial safety, fact-check и education-vs-advice rules описаны;
- competency usage и game action rules используют Gate 2 IDs;
- privacy/B2B boundary явно запрещает доступ работодателя к личным ответам,
  ошибкам, привычкам и финансовым данным;
- human decisions before Gate 4 зафиксированы;
- следующий шаг указан как Gate 4 / Macro Arc after human approval;
- документ не содержит Macro Arc, Section Grid, Emotional Model, Traceability
  Matrix, Lesson Cards, Screen Scripts или генерацию 80 уроков.
